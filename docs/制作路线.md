# CS2 地图工坊（cs2-map-workshop）

用官方与已验证的工具链，按真实地理数据制作《城市天际线2》地图。
工作方式：**机主在对话里用自然语言提要求 → Agent 做全部制作/修改/查证 → 交付机主在游戏内验收**。
长期用途：本工作区服务于**多座城市**的地图制作；换城市时按「六、换一座新城市」入门。

> 生成机器：家用机（MS-7D99 / i5-14600KF / 32GB / RTX 4060 Ti / Win11）
> 本工作区自 2026-09-29 起自 `<private-workspace>\work\cs2-harbin-map` 迁出独立运作；
> 旧工作区完整保留为只读回退档案，**现行方法以本目录为准**。

### 阶段 0 · 范围与比例 🟢

- 输入：机主给的城市/区域名（或中心点）+ 意向（想框住什么）。
- **预览底图准备（90 的输入，缺了预览就是空白图，90 会全缺即停）**：下载目标省的 Geofabrik
  提取包 `*.shp.zip` 到 `data_common\` → config 设 `region_zip`（工作区相对路径）→
  跑 `92_extract_layers.py --map <id>` 抽 water_a/waterways/roads 三图层到 config `region_shp` 目录。
- 做法：拟 `maps\<id>\<id>.config.json`（center/bounds 按 `playable.px×m_per_px` 等距外推；
  模板抄最近的图 config，**清空所有上一图的值**；`epsg` 按经度选 UTM 带，手工填）→
  `90_range_preview.py --map <id>` 出标注预览。
- 产出：`range_preview.png` + `范围预览-提案.md`。
- 通过标准：**机主确认**边界与比例（依兰 = 中心 46.3150N/129.5570E、14.336 km、1:1）。
- 机主决策点：中心/范围/比例、是否保留某地物。**确认前不做地形。**
- 已验证边界：1:1 比例；其他比例未验证（换算链路理论相同，需一轮验证）。

## 四、通用能力与地图专属参数（分离原则）

**通用（跨图直接复用）**：`shared\pipeline\`、`tools\`、`shared\mod\`、`shared\scripts\`、
`config\game.json`、`shared\docs\`（排障经验/操作卡/配方）。脚本一律配置驱动，不含城市字面值。

**地图专属（换图必须重定）**：全部在 `maps\<id>\` ——

| 类别 | 位置 |
|---|---|
| 城市坐标/边界/UTM/网格/海平面/岸线参数 | `<id>.config.json` 顶层 + `water` |
| 取数口径（OSM 类白名单、Overpass 端点/外扩） | `roads_overpass` / `railways` / `imagery` |

注意：**依兰的具体数值（92.5 m 水位、margin 10 m、剖面参数 height 14/min-above 10/max-grade 2.5/
clearance 8.5/smooth 1500/deepen 20@105–140）是本图的选择，不是普遍规则**；换图时按同工具重算，
方法照旧、数值重定。config 模板 = 抄最近图的 config，逐字段替换。

## 六、换一座新城市：入门清单（Agent 执行）

1. 读 `当前状态.md` 确认没有进行中的图轮次；确认新图 id（拼音，如 `yilan`）。
2. 与机主确认（**一次问清，别挤牙膏**）：① 想框哪里、想保住哪些地物 ② 比例（已验证口径 1:1）
   ③ 有没有铁路/特别诉求（影响后面轮次规划）。
3. 建 `maps\<id>\<id>.config.json`（抄最近图的，逐字段改：center/bounds/**epsg 按经度选 UTM 带**/
   dem.tiles/**可玩区跨几块就列几块（10/11/18 会全用）**/sea_level_m **留 null**/region_zip+region_shp/
   各路径/类白名单；删掉上一图专属块如 restrict_near）。
4. **范围预览底图**：下省包到 `data_common\` → config 设 `region_zip` →
   `92_extract_layers.py --map <id>` → `90_range_preview.py --map <id>` → 交机主定边界。
5. 机主确认前不做地形。确认后按「三、制作路线」阶段 2 的**顺序**推进：
   `10 → 12 → 11 →【人工核对并填 sea_level_m】→ 14 → 16 → 18 → 20 → 22 → 24`，
   一轮一个变化、一轮一次游戏验收。**14/16 在 sea_level_m 为空时会显式停止（2026-09-30 修正），
   别绕过顺序。**
6. 每轮收尾：产物哈希入 `MANIFEST.md`、状态入 `当前状态.md`；涉 mod/E2C 的坑先查 `shared\docs\排障经验.md`；
   脚本已知限制与前置检查看 `shared\pipeline\README.md` 限制表。
7. E2C 导路前记得：**关游戏**改 `OSMImportMod.coc` 四至（排障 §3），备份旧值。

## 八、Git 与版本管理（2026-09-30 建仓）

- **仓库**：本目录本地仓库，分支 `main`，**无远程、不推送**；**提交只由机主明确指示时做**
  （`AGENTS.md` 操作边界 10）。首次提交 `256d11c`（依兰 v1 发布完成时快照，549 文件）。
- **入库**：源码（`shared/pipeline`、`shared/mod`、`shared/scripts`、`tools`）、配置（`config/`、各图
  `*.config.json`）、文档（`README`、`当前状态`、各图 `MANIFEST`、`docs/`）、小体积数据与产物
  （线位/铺轨/街名/资源 JSON、发布图、资源图）、以及 `archive/` 历史留档。
- **不入库**（可重新下载或重新生成；**来源与 SHA256 看 `maps/<id>/MANIFEST.md`、`当前状态.md`**）：
  `.venv/`、`maps/*/saves_backup/*.cok`、`maps/*/data/{dem,osm_hlj}`、`*.npz/*.tif/*.shp/*.dbf`、
  `maps/*/products/imagery/`、两张高度图 `*_world.png`/`*_playable.png`、`maps/*/rail/draw_base*.png`
  与 `_画线底图_*.png`、`data_common/*.zip`。这些文件**留在磁盘上**（备份与部署件照旧可用）。
- **行尾铁律**：`.gitattributes` 设 `* -text` ⇒ Git **永不改字节**。本项目的部署件与存档是按 SHA256
  逐字节对账的，CRLF 转换会让哈希全部对不上——不要改成 `text=auto`。
- **要用大件进版本**：本机已装 `git-lfs 3.7.1`，需要时
  `git lfs track "maps/*/saves_backup/*.cok"` + `git add .gitattributes` 即可。
- 常用：`git log --oneline`、`git show --stat`、`git diff`（纯文本改动都能 diff，含各图 config 与数据 JSON）。
