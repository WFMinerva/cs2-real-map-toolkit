## 二、高度场是什么

由 `scripts/105_export_bridge_data.py` 从 Earth2Cities 导入用的同一份 OSM 算出：

- **2705 个点** = `[世界X, 世界Z, 该点净空(米)]`
- 覆盖 **190 处** OSM 标记的桥/高架结构
- 桥面净空 **10.0 m**；出桥后沿路网做 **160 m** 引道坡（坡度 6.25%）
- 桥面节点 1406 个，引道节点 1299 个
- 其中 13 个点地形低于海平面 113.5 m —— 就是"过水路面"那批

算法：桥节点给满净空 → 沿路网 Dijkstra 向外每米衰减 `净空/引道长度` → 得到连续坡。
详见脚本里的注释。

## 五、如果没成

**方案 B（备选）**：不走「改现有节点」，改成走游戏自己的**工具管线**——
注入 `CreationDefinition{m_Original=旧边, m_Flags=Permanent}` + `NetCourse`（抬高后的曲线），
让 `ApplyNetSystem → GenerateNodesSystem/GenerateEdgesSystem` 按建路那条路径重建。
关键点已经查清：`GenerateEdgesSystem:1433-1451` 会从 `m_Original` 复制 `Game.Net.Elevation`，
只要它非 0，曲线就不会被 `AdjustPosition` 按地形吸附回地面。

参考实现就在手边：Earth2Cities 的 `OsmRoadToolSystem.cs`（已有反编译源码）。

## 六、可调旋钮（设置面板里）

| 旋钮 | 默认 | 什么时候动 |
|---|---|---|
| 净空倍率 | 1.00 | 桥看着太矮/太高。1.0 = 10 m。**改完要重跑扫描看门槛** |
| 节点配对半径 | 2.50 m | 命中太少就放大（但桥下方平行地面路可能被误抬）；误抬就缩小 |

`ClearanceScale` 和 `MatchRadius` 会随设置存档；改净空倍率**不需要**重新生成数据文件。
真要改数据本身（比如换引道长度），重跑 `scripts/105_export_bridge_data.py` 再拷进
`ModsData\HarbinBridgeLift\` 即可。

## 八、v1 崩溃事故与 v2 修正（2026-09-29 03:58）

第一次点「抬升」**游戏原生崩溃**。`Player.log` 的栈直接指到 Mod：

```
Native Crash Reporting — Got a UNKNOWN while executing native code
  at Unity.Entities.StructuralChange:AddComponentEntity
  at Unity.Entities.EntityManager:AddComponent
  at HarbinBridgeLift.BridgeLifter:Lift <0x0138a>
  at HarbinBridgeLift.Setting:Run
  ...UI 按钮回调...
```

三个原因，全部已修：

| # | v1 的问题 | 证据 | v2 的改法 |
|---|---|---|---|
| ① | 对**没有** `Game.Net.Elevation` 组件的节点调 `SetComponentData<Elevation>` | 扫描报告白纸黑字：`命中节点里已有 Game.Net.Elevation 的 0 个` | 新增 `ApplyElevation()`：**有就 Set，没有就 Add**。绝不对缺失组件写数据（那不是干净的托管异常，是往错误 chunk 偏移写 → 踩坏内存 → 之后 AddComponent 处原生崩溃） |
| ② | 在 **UI 按钮回调**里做 ECS 结构变更（`AddComponent`） | 栈里的 `ProxyProperty:SetValue → Button:Invoke → GameManager:Update` | 按钮只置标志；真正的读写在新增的 `BridgeLiftSystem`（**ModificationEnd 相位**）里做，结构变更全部走 `EntityCommandBuffer` 批量提交 |
| ③ | 用 `new Entity{Index=.., Version=0}` 重建 prefab entity 去查组件 | 扫描报告里门槛全是 `NaN`、prefab 名全是 `Entity(16060:0)` | 字典 key 直接用完整 `Entity`（带 Version） |

顺带修掉的还有：扫描报告里每个 prefab 出现两次（`new List<KVP>(dict)` 已经拷了一份，我又 foreach 加了一遍）。

**存档没被污染**：崩溃时没保存，`harbin_base4.cok` 的 SHA256 与备份逐字节一致（已核）。

v2 额外加的韧性：还原时的节点匹配**先用 `Entity.Index`，再用世界坐标兜底**（跨存档后索引可能变），报告里会分别列出两种匹配的数量。
