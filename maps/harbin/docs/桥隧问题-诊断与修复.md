# 哈尔滨路网导入 —— 高架重叠 / 跨江桥过水 的诊断与修复方案

生成时间：2026-09-29　针对存档：`harbin_base4.cok`
（本文所有数字都由脚本实测得出，脚本见 `scripts/102*.py`、`103*.py`、`104*.py`，只读不改）

---

## 0. 结论摘要

两个问题是**同一个根因**：

> **Earth2Cities v0.0.17 完全没有处理 OSM 的 `bridge` / `tunnel` / `layer` 标签。**
> 它把每一个路网点的高度**强制覆写成该点的地形高度**，所以：
> - 高架桥 = 贴地 → 与它下面同名的地面路**压在一起**（重叠）
> - 跨江桥 = 落在河床上 → 河床比水面低 → **过水路面**

这不是我们的数据问题，也不是参数没调对，**是官方 Mod 的能力边界**。

---

## 1. 根因（反编译证据）

反编译产物：`decompiled/e2c/OSMImportMod/`（`ilspycmd` 从 `Earth2Cities.dll` 出）

| 位置 | 代码 | 含义 |
|---|---|---|
| `RoadImporter.cs:689-708` | `GeoToTerrainAlignedLocal3D()` 返回 `new float3(x, 0f, z)` | 投影只算 XZ，**Y 先给 0** |
| `RoadImporter.cs:341-360` | `if (TerrainHeightSampler.TrySampleHeight(...)) y2 = height;` … `point.y = y2;` | **Y 被地形高度覆写**；采样失败才回落到 `ImportElevation`（默认 500，`Setting.cs:689`） |
| `TerrainHeightSampler.cs:57` | 只调 `TerrainUtils.SampleHeight` | **只看地形，不看水面** |
| `OsmToRoadsJsonConverter.cs:57,101,126,148,263,293` | 只读 `highway` / `name` / `maxspeed` / `oneway` / `junction` / `lanes*` / `surface` | **`bridge`、`tunnel`、`layer` 从未被读取** |
| `RoadData.cs` / `PointData.cs` | `id,name,category,one_way,lanes,speed_kph,points{lat,lon,junction}` | **roads.json 里没有任何高程字段**，所以改数据也做不到 |
| `OsmRoadToolSystem.cs:378,424` | `m_Elevation = new float2(position.y, position2.y)` | 直接把**绝对 Y** 塞进 `NetCourse` |
| 游戏侧 `NetToolSystem.cs:1032` | `Y = max(水面, 地形) + m_Elevation`（elevation ≥ 0 时） | **游戏自己的道路工具本来会参考水面**，而 Earth2Cities 绕过了它 |

实测佐证（`OSMImportMod.Mod.log` 2026-09-29 03:26:29）：

```
Applied import Y=500.0, range Y [107.7, 166.8]
Terrain sampling: 47798 hits, 0 misses     ← 0 次失败 ⇒ 500 这个回落值一次都没用上
```

`ImportElevation` 这个滑条**只在采样失败时才生效**，所以调它对桥没有帮助。

我用本项目自己的高度图 `out/harbin_playable.png` 重算同一批点的地形高度，最低 **107.8 m**，
与 Mod 在游戏里量到的 **107.7 m** 相差 0.1 m —— 互证通过，说明下面所有数字都对应游戏里真实的地形。

## 2. 后果一：高架与其同名地面路「重叠」

OSM 里高架是 `bridge=yes` 的 way，它下面的地面街是同名的另一条 way。
两者都贴地导入 → 在同一位置画两遍。

| 22 | 文昌高架桥 | 文昌街 |

## 3. 后果二：跨江桥落进河床 → 过水路面

判据只有一个：**该点的地形高度 < 海平面 113.5 m**。

全路网 29,735 个路网点引用中，**低于水面的是 44 个**，落在 **20 条 way** 上
（7 条带 `bridge`，13 条普通路），最低地形 **107.8 m**（水面下约 5.7 m）。

典型剖面（沿桥逐节点地形高度，单位 m）：

| 桥 | 节点地形高度 | 判定 |
|---|---|---|
| 松花江公路大桥 | 123.9 / 125.8 / 124.3 / **111.1** / **111.1** / **111.1** | 桥面扎进水里又爬出来 |
| 松北大道 | 124.3 / **111.1** / **111.1** / 122.5 | 同上 |
| 滨北公铁两用桥 | 116.2 / 117.4 / **111.1** / 118.9 | 同上 |
| 松浦大道 | 122.0 135.3 131.6 127.7 136.0 119.9 117.1 123.9 | 全部 ≥117 m，**不是水中** |

> 说明：我先用 OSM 水面多边形做过一版，得出「40 处跨水、松浦大道全线 1870 m 在水中」——
> **那是虚警**（OSM 水面里混着不在本图海平面上的小河、泡子）。
> 以我们自己的高度图复核后，松浦大道那几条地形在 117–136 m，根本不在水里。
> 下面这张表是**复核后**的口径。

20 条 way 明细见 `out/underwater_spots_table.md`，位置见标注图 `out/bridge_issue_map.png`。

其中 13 条是**没标 bridge 的普通路**却泡在水里，例如 `松北一路`、`雪景街`、`月亮湾·环岛路`、
`滨北街`、`龙唐街`、`河山街`。这批要么是我们水面画宽了，要么是真的漫滩，**建议单独看一下**。

## 4. 顺带一个你没提的问题：隧道

OSM 里还有 **73 条 `tunnel=yes` 的 way**（另有 `layer` 364 条）。
同样因为标签被忽略，**它们现在全部是地面路**。
好消息：这 73 条里**没有一条**的地形低于水面，所以不会出现"水下隧道"这种怪象，
但"该钻地的没钻地"是存在的。

## 5. 三条修复路线

### 路线 A：写一个补充小 Mod，一键抬升（推荐）

**不重做轮子**——抬桥这件事 Earth2Cities 根本没做，不是它已有的能力。
而且它自己就提供了现成的写法可以照抄：
`RoadCleaner.OffsetTaggedImportedRoads()`（`RoadCleaner.cs:179-280`）——
查 `Node` 改 `m_Position`、查 `Edge` 平移 `Curve.m_Bezier`、再挂 `Updated` 让游戏重建几何。
它自己的「Move Imported Roads」按钮就是这么实现的。

做法：把该按钮的**全局固定偏移**换成**按桥数据逐点的高度**：

1. 我从 OSM 导出桥折线（含 `bridge` / `layer` / 长度），给每个节点算目标高度
   = `max(水面, 地形) + 净空`，两端自动做引道坡；
2. 补写 `Game.Net.Elevation` 组件；
3. 抬升前把原 Y 存成 json，配一个「还原」按钮。

- 我这边：一次写完 + 一次编译（构建配方已有，`HarbinRoadImport` 那套能用）
- 你那边：载入 `harbin_base4` → 点一下 → 存成 `harbin_base5`
- **唯一不确定点**：抬高节点后**桥墩/桥面结构能不能由游戏自动生成**。
  参考实现只搬过平移，没搬过高程。这个**点一下就知道**，一次就能验证。
- 全程可撤回：存档先备份，Mod 里带还原。

### 路线 B：我给你清单，你在编辑器里手工抬

标注图 `out/bridge_issue_map.png` + 明细表已备好。
在编辑器里用道路工具沿线拖高程即可。

- 零风险、零新代码，而且**成品最好看**（你能顺手做出引道和匝道）
- 代价：20 处水下 + 68 处高架 ≈ 88 次操作

### 路线 C：只修水里的（最小动作）

只处理 20 处水下路段，高架先放着。10 分钟能做完。
