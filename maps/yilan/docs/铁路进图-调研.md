# 铁路进图 · 可行性调研（依兰）

> 调研完成：2026-09-29/30（子代理，证据截至 2026-09-29）。定性标注：〔已确认〕=一手来源实抓；〔判断〕=基于证据的推断；〔未确认〕=查不到。

## 一句话结论

**自动导入铁路：现成工具没有**（E2C 无此功能也无路线图；唯一先例是个人专用 WIP）。
**手工铺线：官方编辑器原生支持**，30–90 分钟，铺到图边自动生成铁路对外连接（checklist 正式 Optional 项）。
**车站：编辑器不能放**，开局后游戏内建站 20–40 分钟。推荐走官方手工路线，总投入 <2.5 小时。

- Asset Browser 搜 "Train Track"：Double / Oneway / Twoway 三种，可拖画曲线/高程/高架/桥梁。

- 来源：cs2.paradoxwikis.com 的 Map Creation: Outside Connections / Settings and Polish / Editor Basics（2026-06-25 版，官方认证适用 1.6.0 f1）。

## 6. 程序化建网/建站：配方已拿到（IL 实证）〔已确认〕

**① 建网（公路/铁路通用，差别只在预制件）** —— 照抄 `Earth2Cities.dll`
（内部命名空间 `OSMImportMod`）出货版 `OsmRoadToolSystem.CreateEdgeRequest`：

```csharp
// ecb = World.GetExistingSystemManaged<Game.SafeCommandBufferSystem>().CreateCommandBuffer()
var e = ecb.CreateEntity();
ecb.AddComponent(e, new Game.Tools.CreationDefinition { m_Prefab = <TrackPrefab 实体>, m_Flags = …, … });
ecb.AddComponent(e, new Game.Tools.NetCourse {
    m_StartPosition = <CoursePos>, m_EndPosition = <CoursePos>,
    m_Curve = new Bezier4x3(a,b,c,d), m_Elevation = new float2(h0,h1),
    m_Length = math.distance(...), m_FixedIndex = -1 });
ecb.AddComponent(e, new Game.Tools.OwnerDefinition { … });
ecb.AddComponent(e, new Game.Common.Updated());
```

配套：把自己设为 `ToolSystem.activeTool` 并设 `ToolBaseSystem.applyMode`，
原版 `GenerateNodesSystem`/`GenerateEdgesSystem`/`ApplyNetSystem` 就会把它建成真网络
（含车道、几何、地形贴合）。**不需要 Harmony**（E2C 全程无 Harmony；
另一个出货 mod `LineTool` 用同样的定义实体 + `Game.Net.NetUtils.AdjustPosition(curve, TerrainHeightData&)`
贴合地形、`NetUtils.GetNodeRotation(tangent)` 定节点朝向，但它额外用 Harmony 接管工具的"应用"动作）。

**② 放建筑（车站）** —— 同一管线走对象分支：`ObjectDefinition{m_Position, m_Rotation, m_Scale, m_Elevation, …}`
取代 `NetCourse`，配 `CreationDefinition{m_Prefab = 车站建筑预制件}` + `OwnerDefinition` + `Updated`。
编辑器的"不能放车站"是 **UI/工具层面的限制**，程序化注入是否同样被挡 **〔未确认〕→ 必须实测**。

**③ 预制件怎么找**：`PrefabSystem.GetAvailableContentPrefabs()` 遍历 → 按运行时类型名过滤
（E2C 筛 `"RoadPrefab"`）→ 用 `UnityEngine.Object.name` 建字典；兜底反射枚举内部集合。
→ 我们筛 `TrackPrefab`（铁路网）与带 `TransportStation` 数据的 `BuildingPrefab`（车站）。
本图已有已知预制件名：**`Twoway Train Track`**（见第 1 节）。

**类型地图**：铁路运行时标记 = `Game.Net.TrainTrack`（空标记组件，对应公路的 `Game.Net.Road`）；
预制件类 = `Game.Prefabs.TrackPrefab : NetGeometryPrefab`（含 `TrackData`/`TrackLane`/`TrackComposition`，
`TrackTypes {Train, Tram, Subway}`）；站台/车库另有 `TransportStop`/`TransportDepot`。

## 10. v16 断点定位（2026-09-30 凌晨；Game.dll IL 实读 + E2C 出货版逐行对照）

**先撤回 v15 的两条结论**（机主 2026-09-30 指出，成立）：
1. ❌「带 `Temp` 的定义实体消失 = 生成成功」——它只是被别的清理路径删掉了，不是被生成系统消费；
2. ❌「`Temp+NetCourse` 计数 = 原版预览」——那个查询把我们**自己造的**定义实体也算进去了。

**原版查询条件（IL 原文，工具 `tools/ilfind.ps1` / `ildump_il.ps1` 导出，产物在 `maps/yilan/rail/il/`）**：

| 系统 | 查询 |
|---|---|
| `GenerateNodesSystem.m_DefinitionQuery` | All{`CreationDefinition`,`Updated`} Any{`NetCourse`,`ObjectDefinition`} |
| `GenerateEdgesSystem.m_DefinitionQuery` | desc0 All{`CreationDefinition`,`NetCourse`,`Updated`} ∪ desc1 All{`Updated`} Any{`Node`,`Edge`} None{`Deleted`} |
| `GenerateEdgesSystem.m_CreatedEdgesQuery` | {`Created`,`Edge`,`BuildOrder`}，**排除 `Temp`** |
| `ApplyNetSystem.m_TempQuery` | All{`Temp`} Any{`Node`,`Edge`,`Lane`,`Aggregate`} |
| `ApplyNetSystem` 字段 | `m_ToolOutputBarrier`/`m_SimulationSystem`/`m_TriggerSystem`/`m_ApplyCreatedTypes`… **没有 ToolSystem，也没有 applyMode** |
| `NetToolSystem/CreateDefinitionsJob.CreateStraightLine` 造的定义 | `CreationDefinition`+`Updated`+`OwnerDefinition`+`NetCourse`+`LocalCurveCache`（**无 `Temp`、无 `Edge`**） |

**E2C 出货版时序**（`archive/decompiled/e2c/OSMImportMod/OsmRoadToolSystem.cs`，行号）：

- 行 90 `OnCreate`：`applyMode = Clear(2)`
- 行 154 `OnUpdate` 每帧开头：`applyMode = Clear(2)`
- 行 165：有活 → `applyMode = None(0)`，定义实体写进 **`ToolOutputBarrier`** 的 ECB（行 168）
- 行 186–189：`tempQuery`（`WithAll<Temp>`）非空 → `applyMode = Apply(1)`
- 行 392–396 定义实体组件：`CreationDefinition`+`NetCourse`+`OwnerDefinition`+`Updated`（**不加 Temp**）
- 注册相位 `(SystemUpdatePhase)17` = **ToolUpdate**（与我们的注册一致 ✓）

**v15 的两个偏差 = 短轨不出边的根因**：
1. ECB 用了 `Game.SafeCommandBufferSystem`，而**不是** `ApplyNetSystem` 回放的 `ToolOutputBarrier`；
2. `applyMode` 直接顶到 `Apply`，缺 `Clear`/`None` 与「等 Temp 预览出现再 Apply」的握手。

**v16 的唯一机制改动**：按上表把 `RailLayToolSystem` 逐行同构成 E2C 时序。
诊断口径同时修正为三类分开数：① 本轮请求（带 `RailTestMarker` 的定义实体）
② 原版临时网实体（`Temp`，与①分开）③ 永久铁路（`Edge` 且无 `Temp` 且预制件 = 运行时按名字解析出的那个）；
**清理只按 marker**，不再按预制件清（同一预制件上可能有别的工具/玩家的对象）。
预制件身份改为**运行时按名字解析**（记录里的 `prefab_index/version` 只当线索）。

## 11. 车站接线机制（2026-09-30 车站轮，IL 实证；「无轨道连接点」真因）

**现象**：程序化放置 `TrainStation01`（`CreationDefinition`+`ObjectDefinition`+`Updated`，⑧ 按钮）后建筑生成、位置/朝向精确，但游戏弹**「无轨道连接点」**，站内轨道与正线不连通。

**① 提示的判定（IL：`Game.Net.ConnectionWarningSystem/CheckOwnersJob::CheckNodeConnections`，
证据 `maps\yilan\rail\il\stationconn_warn_il.txt:6109+`）**：遍历节点 `SubLane` 里**带
`Game.Net.TrackLane`** 且 `EdgeLane.m_EdgeDelta` 命中该端点(0/1) 的车道；在 `nodeConnections` 里
按 `(conn.m_TrackTypes & lane预制件.TrackLaneData.m_TrackTypes) == 前者的 TrackTypes` 查连接，
查不到就在**该车道端点**打 `TrafficConfigurationData.m_TrackConnectionNotification`（`stationconn_keys.txt:2-6`）。
⇒ 警告单位是**轨道车道的端点**，不是建筑本身。

**② 官方怎么接线（三条 IL 证据）**
1. `Game.Tools.ObjectToolBaseSystem/CreateDefinitionsJob::CreateSubNet`
   （`stconn2_objtoolbase_createsubnet_il.txt:3+`）：放建筑时，工具**为建筑的每条站内子网单独发一个定义实体**——
   `CreationDefinition{m_Prefab = 子网的网预制件, m_SubPrefab = 建筑预制件, m_RandomSeed}` +
   `NetCourse{m_Curve = ObjectUtils.LocalToWorld(transform, 子网相对曲线)}`（还调
   `NetUtils.AdjustPosition` 贴合地形/水面）。即**站内轨道是"跟着建筑一起生成的网"，不是建筑的附属件**。
2. `Game.Prefabs.ObjectSubNets`（建筑预制件上；`stconn2_subnet_refs_prefabs.txt:5-42`
   = `ApplyPrefabsSystem::UpdateObjectSubNets/ListObjectSubNets`）：由预制件的 `Game.Net.SubNet`
   模板缓冲派生出 `ObjectSubNetInfo[]`，每条含 **`m_NetPrefab` / `m_BezierCurve`（相对建筑的曲线）/
   `m_NodeIndex` / `m_ParentMesh` / `m_Upgrades`**。⇒ **站内轨道的几何与预制件可在运行时从预制件读到**，
   世界端点 = `LocalToWorld(建筑 Transform, m_BezierCurve)`。
3. `Game.Net.SubReplacement`（字段 `m_Prefab/m_Type/m_Side/m_AgeMask`；**`SubReplacementType` 只有
   `None`/`Tree`**，`stconn2_subreplacement_refs.txt:73-79` + `gamenet_types.txt:801-814`），由
   `GenerateEdgesSystem/GenerateEdgesJob::GenerateEdge(…, DynamicBuffer<SubReplacement>, …)` 消费并挂到
   生成的边上（同文件 44-67）、`ApplyNetSystem/HandleTempEntitiesJob` 回放（同文件 6-8）。
   ⚠️ **修正**：从枚举只有 Tree 看，它更像"子网替换**植被/树**"的记账，**不是**"把既有轨道换成站内轨道"；
   早期把这步当成"官方换轨"的理解**不成立**。官方接线更可能来自工具生成过程中与既有节点的**节点合并**
   （`NodeReductionSystem` 只在工具生成过程中生效）——这正是我们 v27 用 `CoursePos.m_Entity` 显式复刻的东西。

**③ 我们缺了什么**：⑧ 只发了建筑的 `ObjectDefinition`，**没发 ②-1 的站内子网定义实体、也没写 ②-3 的
替换关系** → 站内轨道没有被生成成"接到既有边上的网"，于是车道端点悬空 → 提示。

**④ 可用的接线开关（备用/辅助证据）**
- `CoursePos.m_Entity` = **把新课程端点直接挂到既有节点实体**上：
  `NetToolSystem` 3546/3550 `m_StartPosition.m_Entity = edge2.m_Start; m_EndPosition.m_Entity = edge2.m_End;`、
  3409/3413 同款（`startPoint.m_OriginalEntity`）。⇒ v27 若走"正线端点吸附站内节点"，用这个字段。
- `Game.Tools.NodeReductionSystem/NodeReductionJob`（`nodereduce_il.txt:470-530`）只在**工具生成过程中**
  按 `ReductionData{m_EdgeLengthRange,m_SnapCellSize}` 合并节点（含 `m_ForbidMove` 分支）
  ⇒ **不能指望"事后两次独立生成"的节点自动合并**；要连通必须显式引用节点实体或走 ② 的替换路径。

**⑤ 方案定稿（2026-09-30，v26 诊断后）**
- **必做 P1（生成站台轨道）**：⑧ 按预制件 `Game.Prefabs.SubNet` 逐条发
  `CreationDefinition{m_Prefab=子网预制件, m_SubPrefab=车站预制件}` + `NetCourse{LocalToWorld(本地曲线)}`。
  **v28 已实现**。

  顺序**先⑧后⑦**。**v27 已实现**（裁剪法，不依赖 60 m 网格对齐）。
- 报告口径：站内 `SubNet` 实体/节点世界坐标、轨道车道 `TrackTypes`、站内端点到正线节点距离、

### 11.1 v26 诊断实测结论（2026-09-30，决定方案取舍）

### 11.3 v30/v31 失败链与「站内网只有节点、没有边」的实测（2026-09-30）

- **v30 实拍事故**：节点筛选只按横向距离 → 选中 y≈111.4 m 的节点；且挂接端仍带 `FreeHeight(128)`

  已修：① 挂接端只留 `IsFirst/IsLast`（不带 FreeHeight）；② 节点筛选加"轨道节点 + 贴轨面 ±2.5 m"门槛。
- **v31 实拍仍不行（机主「不行」），但暴露了根因**：⑧ 之后车站建筑的 `Game.Net.SubNet` 缓冲里
  **33 条全是 `Node`、0 条 `Edge`** ⇒ **P1 只建出站内网的节点，没有建出站内轨道边**。因此：
  - 车站的"站内轨道"在网络上**并不存在** ⇒ 正线没有可接的对象；
  - 之前机主看到"正线接上月台轨"其实是**正线穿过站台**的视觉重合（原版 overlap 合并的观感），
    不是真接线；
  - v31 的节点筛选因"节点都没有边"判不出轨道节点 → 候选 **0 个** → 回退用了列表前两个任意节点
    （恰是隐形道路节点）⇒ 把线截在错误位置（机主实拍）。
- **当前对策**：数据置 `trim_span: false`（回到"正线穿过车站"的通过式；位置/朝向已按真实站房校正），
  先保住可用外观。**"站内轨道边为何没生成"另立专项**，候选原因：定义实体缺 `LocalNodeCache`/
  `LocalTransformCache`；`m_SubPrefab` 在非 EditorContainer 场景应为 `Entity.Null`；或需
  `CreationFlags.Permanent`；或 `OwnerDefinition` 的挂接需要对象实例先存在（生成顺序）。

### 11.4 v32 定案：`m_SubPrefab = Entity.Null` ⇒ 站内轨道边生成、接线成立（2026-09-30）

- **根因（候选清单里的第一条被证实）**：站内子网定义里 `CreationDefinition.m_SubPrefab` **必须是
  `Entity.Null`**。填"车站建筑预制件"（11.2 的做法）会被 `GenerateEdgesJob.GenerateEdge(…,
  DynamicBuffer<SubReplacement>, …)` 当成**替换关系**处理 ⇒ 只建节点不建边（v31 实测 33 Node / 0 Edge）。
  官方 `ObjectToolBaseSystem/CreateDefinitionsJob::CreateSubNet` 只在对象带 `EditorContainer` 时才填
  `m_SubPrefab`，普通建筑场景就是 `Entity.Null`。
- **最终配方（每份站内子网一条）**：
  `CreationDefinition{m_Prefab = 子网的网预制件, m_SubPrefab = Entity.Null}` +
  `NetCourse{曲线 = LocalToWorld(本地曲线), m_Elevation, m_Flags = 0}` +
  `OwnerDefinition{m_Prefab = 车站预制件, m_Position = 建筑世界位置, m_Rotation = 建筑旋转}` + `Updated`
  + `StationMarker{variant = 1}`。
- **⑧ 实测**：站内 `Game.Net.SubNet` = **Edge 19 / Node 33 / 其它 0**（此前 0 边）；
  建筑落位 `(3322.3, 100.69, −4223.5)`、平面偏差 **0.00 m**、yaw 差 0.0°、地形 100.65（差 +0.04 m）。
- **⑦ 接线实测**：节点筛选 33 → **轨道节点且贴轨面(±2.5 m) 6 个** → 取离线位最近的两个：
  SW `175207v3`（横距 **0.03 m**）/ NE `175208v3`（横距 **0.02 m**），**跨距 212.0 m**；
  裁掉站内跨距课程 **3 条**、挂接课程端 **4 个**；连接实况 = **4 个站内节点有外来边** ⇒ 接线成立。
  机主实拍「这回应该是连上了」。
- **同时修掉的另一个坑**：⑧/⑦ 各自需要**独立的 5 秒后续自查定时器**；共用同一个时点得快，后者会把前者的
  报告挤掉（v31 只出 9 行、看不到 ⑧ 的分类结果）。
- **数据侧配套**：`trim_span: true`（⑦ 自动截断站内跨距并接站内节点）；`yaw_offset_deg = −90`
  （月台轨沿 local X）；`lateral_m` = 8.5 / 24 / 40 分别让**最近 / 中间 / 最远**那条月台轨压线，
  本轮定 **24** ⇒ 正线走中间轨、两侧各一条月台轨（机主要求）。
- 后续（同轮）：站区线位对齐真实哈佳线 **44.90°**（`tools/_rail_align_station_real.py`）、
  站区轨面由 14 m 路基降到**地面线 100.69 m**（`tools/_rail_grade_station.py`）、车站 y 随之下调；
  见 `当前状态.md` R8 与 `rail\README.md`。
